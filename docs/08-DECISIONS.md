# 08. Решения, допущения, открытые вопросы

## Принятые решения (владелец подтвердил или делегировал)

| № | Решение | Основание |
|---|---|---|
| D1 | Drizzle ORM, не Prisma | SQL-миграции, лёгкий рантайм, одинаково работает с локальным Postgres и Supabase |
| D2 | Два окружения через адаптеры, разработка на Docker, Vercel + Supabase как переключаемая цель | делегировано владельцем |
| D3 | Google Drive через OAuth владельца, а не через сервисный аккаунт | у сервисного аккаунта нет квоты хранилища, загрузка падает без Shared Drive |
| D4 | Загрузка файлов всегда двухшаговая (сессия + прямая загрузка) | лимит тела запроса ~4.5 МБ на Vercel, фото с телефона крупнее |
| D5 | Своя аутентификация за интерфейсом `AuthProvider` | вход по телефону, аккаунты создаёт суперадмин; переход на Supabase Auth возможен без переписывания |
| D6 | Авторизация в приложении, без RLS | одна точка правды по правам; RLS = вторая копия логики |
| D7 | `org_id` заложен, создание сетей в UI выключено | делегировано владельцем |
| D8 | Сброс пароля: разрешение админа + вход с любым паролем + принудительная смена | выбор владельца; осознанно слабое место, каждое использование в аудите, разрешение живёт 24 часа и одноразовое |
| D9 | Деньги — целые тенге, округление долей вверх, излишек дому | правило владельца |
| D10 | Двойная запись в бухгалтерии | иначе переводы между фондами не сходятся |
| D11 | Роль и проживание — разные сущности | админ одновременно жилец |
| D12 | Слот ротации привязан к месту (bed_id), а не к человеку | сменился жилец — позиция в цикле сохраняется |
| D13 | Web Push + PWA сразу, e-mail и SMS не делаем | выбор владельца |
| D14 | Ставки налога 3 % и эквайринга 0,95 % — настройки, не константы | ставки меняются, ответственность за значения на владельце |

## Разрешённые противоречия исходного ТЗ

| № | Противоречие | Как решено |
|---|---|---|
| C1 | «Коммуналка не взимается за дни отсутствия» против «перерасчёт недопустим» | плата за проживание всегда полная; коммуналка — по фактическим дням. Подтверждено владельцем |
| C2 | «Заморозить личный цикл отсутствующего» против «цикл считается по id кровати» | реализована детерминированная сетка по номеру недели; отсутствие даёт `needs_reassignment` и задачу админу, а не автоматический сдвиг. Личные счётчики ломают уникальность назначений |
| C3 | Оплата при выезде в середине месяца | берётся полный месяц; перерасчёт только вручную, отдельной корректировкой |

## Решения фазы 0 (каркас)

| № | Вопрос | Принято | Файлы |

| P0-1 | Версия TypeScript: 7.0.2 — последняя | **TypeScript 6.0.3, не 7.** `typescript-eslint` работает через классический API TypeScript и вызывает `getTypeChecker()`, которого нет в поверхности `tsgo`. Это несовместимость API, а не отставание версий; форки-мосты не подключаем. **Пересмотреть, когда `typescript-eslint` официально закроет поддержку TS 7** | `package.json`, `tsconfig.json` |
| P0-2 | Нужен ли префикс локали в URL | **Нет.** Локаль — атрибут пользователя (`users.locale`), в `06-API.md` пути без локали. Источник: cookie `NEXT_LOCALE`, с фазы 1 — профиль | `src/lib/i18n/*` |
| P0-3 | Что содержит первая миграция | Только инфраструктура: расширение `btree_gist` (понадобится для `EXCLUDE` в фазе 2) и таблица `job_runs`. Прикладные таблицы создаются в своих фазах | `src/db/migrations/0000_*` |
| P0-4 | Какие компоненты `ui/` входят в фазу 0 | Простые примитивы. `Combobox`, `DatePicker`, `Drawer`, `Calendar`, `SignaturePad`, `FileUpload`, `ChecklistEditor` — в фазах, где впервые нужны | `src/components/ui/*` |
| P0-5 | Состав `pnpm verify` | `typecheck + lint + format:check + test`. `build` и e2e — отдельные шаги CI. Prettier не трогает Markdown: документация — источник истины и не переформатируется механически | `package.json`, `.prettierignore` |
| P0-6 | Как собирать без секретов в CI | Без escape-hatch `SKIP_ENV_VALIDATION`. В CI задаются тестовые значения переменных | `.github/workflows/*` |
| P0-7 | Где хранится выбранная тема | В фазе 0 только `localStorage`: таблицы `users` ещё нет. Синхронизация с профилем — фаза 1 | `src/components/theme/*` |
| P0-8 | Что делает сервис `worker` в фазе 0 | Пустой скелет node-cron: старт и лог, заданий нет. Задания — фаза 6 | `src/workers/index.ts` |
| P0-9 | Когда появляются `domain/money.ts` и `lib/time.ts` | Уже в фазе 0, хотя роадмап относит пример §0.1 к фазе 3. Без них не проверяется инвариант «никакого `new Date()` в бизнес-логике», и Vitest нечем проверить | `src/domain/money.ts`, `src/lib/time.ts` |
| P0-10 | Считается ли локальная сборка с `DEPLOY_TARGET=vercel` проверкой развёртывания | **Нет.** Она подтверждает только сборку бандла: ни пулер соединений, ни лимит тела запроса, ни serverless-рантайм так не проверяются. Реальный превью-деплой делает владелец по `docs/DEPLOY-VERCEL.md`; без этого файла фаза не закрывается | `docs/DEPLOY-VERCEL.md`, `vercel.json` |

## Открытые вопросы

Формат записи для агента:
`[ОТКРЫТО] <вопрос> — принял: <решение> — файл: <путь>`

- `[ОТКРЫТО]` Порог перезарядки рейтинга: сейчас порог взводится сразу при возврате к `>= T`,
  что допускает колебания 39↔40 с повторными санкциями. Заложить настройку
  `rearm_margin` (по умолчанию 0) и вынести в правила. — принял: настройка есть, значение 0.
- `[ОТКРЫТО]` Что делать, если у ряда ротаций мест меньше, чем требуется людей на зоны (`D > S`):
  сейчас сохранение блокируется с ошибкой. — принял: блокировать.
- `[ОТКРЫТО]` Переоткрытие закрытого периода коммуналки после того, как доли попали в счета:
  сейчас разрешено только суперадмину и требует ручного пересчёта затронутых счетов.
- `[ОТКРЫТО]` Поддержка TypeScript 7 (`tsgo`) в `typescript-eslint` отсутствует: линтер вызывает
  `getTypeChecker()` классического API. — принял: остаёмся на TS 6.0.3, пересмотр после
  официальной поддержки TS 7 в `typescript-eslint` — файл: `package.json`
- `[ОТКРЫТО]` Ставится ли `btree_gist` на Supabase без прав суперпользователя: миграция написана
  идемпотентно и при `insufficient_privilege` выдаёт `WARNING`, а не падает. Фактически на Supabase
  ещё не проверено. — принял: проверить при первом превью-деплое и дописать результат сюда —
  файл: `src/db/migrations/0000_*`
- `[ОТКРЫТО]` Превью-деплой на Vercel не выполнялся из среды разработки. — принял: подготовлена
  пошаговая инструкция для владельца — файл: `docs/DEPLOY-VERCEL.md`
- `[ОТКРЫТО]` Поведение `splitCeil` в вырожденных случаях (пустой список участников,
  все веса нулевые, дробная сумма или дробный вес) в §0 не описано. — принял: выбрасывать
  ошибку вместо тихого зачисления всей суммы в фонд дома: деньги должны терять не молча —
  файл: `src/domain/money.ts`
- `[ОТКРЫТО]` ESLint 10.10.0 несовместим с `eslint-config-next@16.3.4`: парсер Next
  (`eslint-config-next/parser`) не реализует `ScopeManager#addGlobals`, которого ESLint 10
  требует при объявленных глобальных переменных — линтер падает на любом файле.
  — принял: ESLint 9.39.5, пересмотр после появления поддержки ESLint 10 в `eslint-config-next` —
  файл: `package.json`, `eslint.config.mjs`
- `[ОТКРЫТО]` pnpm 12 больше не читает настройки из поля `pnpm` в `package.json` и использует
  ключ `allowBuilds`, а не `onlyBuiltDependencies`. — принял: настройки в `pnpm-workspace.yaml`,
  сборочный скрипт разрешён поимённо только `unrs-resolver` — файл: `pnpm-workspace.yaml`
- `[ОТКРЫТО]` Форматирование дат и чисел в интерфейсе: зона не задана в ТЗ явно для UI.
  — принял: `timeZone: 'Asia/Almaty'` задан в конфиге next-intl, поэтому весь вывод дат
  идёт в зоне расчётов — файл: `src/lib/i18n/request.ts`
- `[ОТКРЫТО]` Минимальная длина `SESSION_SECRET` и `CRON_SECRET` в ТЗ не задана.
  — принял: 32 и 16 символов соответственно, проверяется схемой — файл: `src/lib/env/schema.ts`
- `[ОТКРЫТО]` `DIRECT_DATABASE_URL` обязателен или нет: в ТЗ помечен как «для миграций на Supabase».
  — принял: необязателен; когда не задан, drizzle-kit использует `DATABASE_URL` —
  файл: `src/lib/env/schema.ts`, `drizzle.config.ts`
- `[ОТКРЫТО]` Значение `TZ`: бизнес-логика от системной зоны не зависит (расчёты идут через
  `src/lib/time.ts` с фиксированным UTC+5). — принял: переменная не ограничена конкретным
  значением, по умолчанию `Asia/Almaty` — файл: `src/lib/env/schema.ts`
- `[ОТКРЫТО]` Разбор окружения нельзя тестировать прямо в `src/env.ts`: пакет `server-only`
  бросает исключение вне серверного рантайма. — принял: чистая схема и `parseEnv` вынесены
  в `src/lib/env/schema.ts`, `src/env.ts` остаётся тонкой серверной обёрткой —
  файл: `src/env.ts`, `src/lib/env/schema.ts`
