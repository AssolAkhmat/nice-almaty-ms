# Модуль 6. Коммунальные услуги

Правила и примеры расчёта — `docs/03-BUSINESS-RULES.md` §4.

## Выбор месяца
- Переключатель показывает месяцы, по которым период уже заведён, плюс текущий и прошлый;
  любой другой месяц открывается полем выбора месяца рядом. Текущий месяц есть в списке
  всегда — это правило, а не следствие расчёта (решение D24).
- Период за месяц заводится **действием**: показ месяца ничего не создаёт. Открывается
  экран по умолчанию на прошлом месяце: коммуналка собирается за него, а заполняют её уже
  в новом.

## Экран периода (месяц, дом)
- Строки: название, сумма, чек (необязательно). Добавление, редактирование, удаление.
- Итого по периоду.
- Таблица предварительного распределения: жилец, дней проживания, дней вычтенного отсутствия,
  доля. Итог, излишек округления.
- Кнопка **«Закрыть период»** — фиксирует снимок распределения (`utility_allocations`),
  дальше строки не редактируются без переоткрытия (переоткрытие — только суперадмин, с аудитом).
- Период без строк закрывается: ноль — законный итог месяца, дом мог не платить. Снимок при
  этом пишется по нулям, а в счета не уходит ничего: строка на ноль тенге была бы мусором
  в документе жильца. Отказ остаётся только у случая «есть что делить, но не на кого».
- Напоминание админу 25 числа.

## Попадание в счёт
- Если период закрыт до генерации счетов 1 числа — доля попадает строкой `utilities`
  в месячный счёт.
- Если нет — счёт выставляется без коммуналки, а при закрытии периода строка добавляется
  в уже существующий счёт того же месяца (с уведомлением жильцу).

## Отчёты
- История коммуналки по дому: месяц, сумма, средняя доля, число жильцов, дней.
- Сравнение домов (суперадмин).
- Экспорт CSV/XLSX.
