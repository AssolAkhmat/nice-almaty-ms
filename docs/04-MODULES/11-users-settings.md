# Модуль 11. Пользователи и настройки

## Пользователи
- Список: телефон, ФИО, роль, дом, статус, последний вход.
- Создание аккаунта (только суперадмин): телефон, роль, дом, временный пароль
  (генерируется, показывается один раз, кнопка «Скопировать»).
- Действия: разрешить сброс пароля (24 часа, одноразово), архивировать,
  сменить роль, перевести админа на другой дом.
- Несколько суперадминов с равными правами. Один админ — один дом.
- Аккаунт нельзя удалить, только архивировать (история должна сохраняться).

## Настройки сети (суперадмин)
- Дома: создание, переименование, адрес, комендантский час, депозит по умолчанию.
- Правила рейтинга, штрафов и скидок (глобально + переопределение на дом, копирование между домами).
- Типы документов и сроки годности.
- Шаблон договора: HTML-редактор + палитра доступных токенов подстановки —
  `{{resident.full_name}}`, `{{resident.iin}}`, `{{residency.contract_start}}`,
  `{{residency.contract_end}}`, `{{bed.room}}`, `{{bed.label}}`, `{{bed.price}}`,
  `{{house.name}}`, `{{house.address}}`, `{{today}}`, `{{resident.id_doc_issuer}}`,
  `{{resident.registration_address}}`, `{{residency.contract_number}}`,
  `{{resident.id_doc_number}}`, `{{residency.deposit_amount}}`, `{{resident.phone}}`,
  `{{resident.emergency_name}}`, `{{resident.emergency_phone}}`, `{{resident.university}}`,
  `{{resident.course}}`, `{{resident.signature}}`, `{{owner.signature}}`. Палитра — источник истины для `unknownTokens()`
  в `src/domain/contract-template.ts`; тест `contract-template.test.ts` держит
  оба списка в согласии.
  Вставка токена кликом, кнопка «Предпросмотр на тестовых данных», версионирование шаблона.
  Подпись жилец рисует на канвасе, файл проходит обычной двухшаговой загрузкой,
  а готовое изображение встаёт на место токена `{{resident.signature}}` — туда,
  где подпись положена по тексту договора (указание владельца, 21 сентября 2026;
  пересмотр P2-17). Это единственный токен, значение которого вставляется
  разметкой, а не экранированным текстом: его собирает сервер из байтов файла.
  Шаблон без этого токена печатается по-прежнему — подпись блоком в конце
  документа, иначе договоры, написанные до появления токена, остались бы
  без подписи вовсе.
  Загрузка готового текста договора (docx/pdf) поддерживается как вложение-образец;
  подставляемый документ формируется из HTML-шаблона.
- Видимость рейтинга у жильцов (вкл/выкл глобально).
- Шапки и футеры шаблонов ротаций (обычная и генеральная), по домам.
- Локализация: список активных локалей, локаль по умолчанию.
- Токены API для ботов: имя, скоупы, срок, отзыв.
- Аудит-журнал: фильтры по актору, сущности, периоду; экспорт CSV.

## Настройки дома (админ)
Зоны и места, цены по умолчанию, чек-листы, группы допуска, ряды ротаций,
шапки/футеры шаблонов, переопределённые правила рейтинга (если разрешено суперадмином).

## Личные настройки (все)
Язык (ru/kk/en), тема (светлая/тёмная/системная), пуш-уведомления, смена пароля.

## Подпись исполнителя

Суперадмин расписывается в настройках сети тем же полотном, что и жилец, и может
подпись заменить (указание владельца, 22 сентября 2026). Изображение встаёт на место
токена `{{owner.signature}}`; шаблон без токена подпись исполнителя не получает —
блоком в конце она не приклеивается.

Подписанные договоры от смены подписи не меняются: при подписании идентификатор файла
запоминается в `residencies.owner_signature_file_id`, и пересборка берёт его, а не
нынешнюю настройку. Та же мысль, что версионирование шаблона в T8.5 — документ,
который уже подписали, задним числом не меняется.

## Приветственное сообщение

Рядом с временным паролем — кнопка «Отправить в WhatsApp»: ссылка `wa.me` с номером
без плюса и пробелов и готовым текстом (указание владельца, 25 сентября 2026).
Пароль показывается один раз, и передать его человеку надо тут же.

В сообщении только адрес приложения, логин (он же телефон) и временный пароль
с указанием сменить его. **Ни ИИН, ни названия дома, ни ФИО** — переписка
в мессенджере остаётся у обоих навсегда.

Текст живёт в словарях трёх локалей и правится суперадмином в настройках сети;
пустое поле возвращает словарный текст. Подстановок ровно три: `{url}`, `{login}`,
`{password}` — остальное остаётся в тексте как есть, и это проверено фикстурой.

## Подпись человека на экране

ФИО из профиля, а если профиль не заполнен — телефон и пометка «профиль
не заполнен» (указание владельца, 25 сентября 2026). **Идентификатор
не показывается нигде**: три дефекта подряд оказались одной природы —
экран подставлял uuid там, где не нашлось имени.

Подпись собирает `personLabels` одним запросом на список, а рисует
компонент `PersonName`, который идентификатор просто не принимает.
Дом жильца берётся из действующего проживания, а не из `users.house_id`:
по D11 у жильца дома в учётной записи нет.

Правило закреплено приёмкой: на странице не должно быть видимого uuid
в тексте — проверяется на всех страницах и на трёх ширинах, с негативной
фикстурой.
