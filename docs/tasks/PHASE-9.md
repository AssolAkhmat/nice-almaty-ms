## Задачи

### T9.1 — Загрузка файлов: прямая загрузка в Drive из браузера
- [x] Разбор двухшагового потока по коду и документации Google:
      сессия открывается сервером без заголовка `Origin`, ответ Drive
      на `PUT` из браузера не несёт CORS-заголовков — браузер прячет ответ
      за `Failed to fetch` (инцидент I11, разбор в `docs/08-DECISIONS.md`)
- [x] Тест-первым: `UploadMeta.origin`, драйвер `gdrive` передаёт `Origin`
      при открытии сессии, роут берёт его из запроса браузера (P9-1)
- [x] Сервисы и роут прокидывают origin; локальный драйвер его игнорирует
- [x] `PROGRESS.md`: что проверено, что проверить нельзя, признаки для
      различения версий в браузере — ссылкой на разбор I11
- Коммит: `fix(files): resumable-сессия Drive привязана к Origin браузера`

### T9.2 — Договор не формируется
- [x] Причина найдена по коду и сборке: на Vercel нет `@sparticuz/chromium` —
      по P2-16 он не входил в зависимости, а боевая собирается из репозитория
      (инцидент I12, P9-2)
- [x] Все server actions ведут сбои в журнал через `actionErrorKey`, под тестом;
      `AppError` по-прежнему уходит ключом на экран без записи
- [x] Пакет в зависимостях, литеральный импорт, `serverExternalPackages`,
      архивы `bin/**` в трассировке функции Vercel — проверено по `.nft.json`
      локальной сборки под `DEPLOY_TARGET=vercel`; в standalone для Docker исключён
- [x] `GET /api/health?pdf=1` проверяет печать на боевой без заведения проживания;
      живьём не проверено — превью-деплоя у разработки нет
- Коммит: `fix(contracts): печать на Vercel и журнал сбоев server actions`

### T9.3 — /profile не открывается
- [x] Причина найдена: место читалось прямым запросом к схеме дома, которой
      жилец не видит (P2-5) — экран падал сразу после назначения места (I13)
- [x] Место читается через своё проживание; проживание берётся по `userId`,
      а не первым видимым (I6)
- [x] Приёмка: жилец с назначенным местом видит его в профиле, три ширины
- Коммит: `fix(profile): место жильца читается через своё проживание`

### T9.4 — Админу назначается место (D11)
- [x] Причина: учётная запись админа не заводила проживание — прежний тест
      фазы 2 это закреплял, вопреки D11. Проживание заводится обеим ролям (P9-3)
- [x] Смена роли заводит проживание, если его нет; проживание не переезжает
      вслед за домом админа (`[ОТКРЫТО]`)
- [x] Кнопка «Завести проживание» у суперадмина для админов, созданных до правила;
      три локали; повторное нажатие ничего не дублирует; запись в `audit_log`
- [x] Негативные фикстуры: суперадмину проживание не заводится, админ не заводит
      его даже себе
- [x] Приёмка: новому админу назначается место; кнопка заводит проживание
      сидовому админу (одна ширина, прогон убирает за собой)
- Коммит: `fix(users): админ — жилец своего дома`

### T9.5 — Переключение локали
- [x] Причина: у вошедшего язык читается из учётной записи, а переключатель

- [x] Переключатель обновляет учётную запись тем же сервисом, что личные настройки
- [x] Приёмка: вошедший переключает язык на казахский и английский, выбор
      переживает перезагрузку; три ширины
- Коммит: `fix(i18n): переключатель языка обновляет учётную запись`

### T9.7 — Смена номера телефона
