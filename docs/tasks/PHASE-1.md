## Места, где документация молчит

Четыре закрыты владельцем до начала работ и записаны в `docs/08-DECISIONS.md`
как P1-1 … P1-4: код ответа на чужой дом, хранилище счётчика попыток,
требования к паролю, устройство матрицы прав.

Остаются четыре, решения по ним приняты и записываются в том же коммите,
где применяются:

1. **Cookie сессии и продление.** Имя `nice_almaty_session`, httpOnly, Secure,
   SameSite=Lax, Path=/. Внутри — непрозрачный токен, в базе только его хеш.
   TTL 30 дней; продление ленивое, при запросе не чаще раза в сутки,
   чтобы не писать в базу на каждый запрос.
2. **Состав `before`/`after` в аудите.** Пишутся только изменившиеся поля, а не вся
   строка. Зашифрованные поля (`iin_enc`, `id_doc_number_enc`) в журнал не попадают
   никогда — вместо значения пишется `"***"` и признак самого факта изменения.
   Раскрытие ИИН и УДЛ кнопкой «глаз» — отдельное событие аудита без значения.
3. **Временный пароль.** 12 символов из алфавита без похожих начертаний
   (без `0OoIl1`), генерация через `crypto.getRandomValues`. Показывается один раз,
   в базе только argon2id-хеш, в журнал аудита не попадает.
4. **Бутстрап первого суперадмина.** Только сид, никаких переменных окружения.
   `pnpm db:seed` создаёт суперадмина с временным паролем, печатает его один раз
   в вывод и ставит `must_change_password = true`.

Схема и чистые функции идут первыми, экраны — после прав и аудита: иначе экраны
пришлось бы переписывать под матрицу прав.

Сид перенесён с T1.15 на T1.9: как только защищённая зона потребовала сессии,
без учётных записей стало нечем проверять ни навигацию, ни права.

T1.10 добавлен по ходу фазы: защита процесса сборки — такое же требование
Definition of Done, как и защита кода.
