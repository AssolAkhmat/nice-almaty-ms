# Фаза SIGNATURES. Три опоры электронной подписи (Приложение №3, пункты 2.4 — 2.6)

Указание владельца 1 октября 2026. Идёт **до первого подписываемого акта**: пункты 2.4,
2.5 и 2.6 — три опоры одной конструкции, на которой держится приравнивание росчерка
к собственноручной подписи (п. 2.8). Из трёх работает одна.

## Что обещано и что есть

| Пункт | Текст | Состояние |
|---|---|---|
| 2.4 | «Первичное подписание… при личном присутствии представителя Исполнителя, после установления личности Заказчика по документу, удостоверяющему личность. **Факт установления личности, дата, время и реквизиты предъявленного документа фиксируются Исполнителем в Системе**» | записи нет вовсе |

| 2.6 | «Вместе с подписью Система сохраняет **контрольную сумму** подписанного документа, исключающую изменение его текста после подписания. По требованию Заказчика Исполнитель предоставляет сведения о сохранённой контрольной сумме» | не считается ни для одного файла: на боевой 386 файлов, контрольная сумма у нуля |

Почему 2.6 не работает: сумму считает только путь загрузки через приложение
(`src/services/files.ts`), а на боевой драйвер `gdrive` — байты идут мимо сервера.
Сборка договора (`storeServerFile`) не считает её вовсе, хотя байты у неё в руках.

## Про задние суммы — честная формулировка (указание владельца)

Хэш уже лежащих файлов посчитать можно и нужно, но называть его суммой подписания
нельзя. Он доказывает неизменность **вперёд**, а не назад. Поэтому:

- отдельное поле и отдельная дата расчёта;
- в интерфейсе и в ответе API — «контрольная сумма, вычисленная <дата>», а не
  «контрольная сумма на момент подписания»;
- у документов, подписанных после внедрения, — сумма подписания, и она называется так.

## Задачи

### S1. Контрольная сумма при сборке документа

- [ ] Сборка договора считает `sha256` по байтам, которые кладёт в хранилище
- [ ] Сумма сохраняется вместе с подписанным документом, а не только у файла
- [ ] Тест: пересборка того же текста даёт ту же сумму, правка текста — другую

### S2. Задние суммы у уже подписанных документов

- [ ] Разовый пересчёт по хранящимся файлам, отдельное поле и дата расчёта
- [ ] Формулировка «вычислена <дата>» в интерфейсе и в API — не выдаётся
      за сумму подписания
- [ ] Тест: поле суммы подписания у таких документов остаётся пустым

### S3. Сведения о подписании рядом с документом (п. 2.5)

- [ ] Устройство, дата, время и сетевой адрес сохраняются вместе с подписанным
      документом, а не только в журнале аудита
- [ ] Жилец видит эти сведения по своему документу (п. 2.6 — «по требованию»)

### S4. Факт установления личности (п. 2.4)

- [ ] Представитель Исполнителя отмечает установление личности: дата, время,
      вид и реквизиты предъявленного документа, кто устанавливал
- [ ] Реквизиты документа — чувствительные данные: шифрование тем же механизмом,
      что ИИН, раскрытие пишется в журнал
- [ ] Отметка обязательна при **первичном** подписании и не требуется при повторных
- [ ] `[ОТКРЫТО]` Блокирует ли отсутствие отметки подписание. Принимаю:
      не блокирует, но подписание без неё помечается, и админ видит признак —
      п. 2.4 требует фиксации факта, а не разрешения на подпись
